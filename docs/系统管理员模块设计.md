# 系统管理员模块设计说明

> 适用范围：`classroom-insight-java`（Spring Boot 3 + MySQL 8 + MyBatis + Thymeleaf）
> 对应代码：`controller/AdminController`、`service/{AdminService,PermService,AuditService,BackupService,SysConfigService}`、
> `mapper/SysMapper`、`templates/admin/*`、`db/schema.sql`（系统管理层 5 张表）
> 验证脚本：`scripts/admin_smoke.ps1`（33 项检查，全部通过）

---

## 一、模块定位与设计原则

### 1.1 定位

系统管理员模块是**独立于教学业务的控制面**：教师、学生只关心"教与学"，管理员关心"谁能用、能做什么、做过什么、数据是否安全、系统是否健康"。
它不产生教学数据，但**为全部业务提供身份、权限、参数、审计与数据安全保障**。

### 1.2 五条设计原则

| 原则 | 具体落地 |
|---|---|
| **配置真正生效** | 参数不是"存着好看"：预警阈值进入风险分级计算，密码策略进入注册/重置校验，登录锁定策略进入认证流程，系统名称实时改顶栏 |
| **权限真正生效** | 权限点不只是在后台打勾：教师端课堂/互动/作业/AI 批改的写操作全部调用 `requirePerm()` 校验 |
| **操作必有留痕** | 成功与失败都写 `operation_logs`，记录"谁、何时、对什么、做了什么、结果、为什么失败、耗时、IP" |
| **危险操作可回退** | 删除用户先查业务引用；恢复数据前强制执行一次自动备份；清理日志文件先提示导出 |
| **失败不扩散** | 监控指标、日志查询、备份引擎均带降级：单项失败只丢失该项，不拖垮整页或主业务 |

### 1.3 角色与权限模型

```
用户 users.role  ──属于──▶  角色（admin / teacher / student）
                                   │
                          role_permission（角色 × 权限点 × 开关）
                                   │
                          sys_permission（24 个内置权限点）
```

- 权限点由代码定义（`SysConfigService.PERM_DEFS`），**不提供增删改接口**，防止权限标识被篡改导致校验失效；
- 管理员在界面上只能调整"角色 × 权限点"的开关；
- **admin 角色权限恒为全部且不可修改**（`PermService` 中硬边界），避免管理员把自己降权后系统无人可管；
- 学生角色不允许开启管理类权限（`user:`/`perm:`/`config:`/`backup:`/`log:` 前缀）。

### 2.3 响应式适配

| 断点 | 布局变化 |
|---|---|
| `> 1100px` | 侧边栏常驻（216px）；指标卡 4 列；双栏网格 |
| `≤ 1100px` | 网格转单栏；指标卡 2 列；健康自检 2 列 |
| `≤ 900px` | 侧边栏变抽屉（默认隐藏，顶栏 ☰ 唤起 + 半透明遮罩），主内容取消左缩进 |

交互细节：移动端点击遮罩或侧边栏"×"收起抽屉；所有写操作均有 Toast 反馈；危险操作（停用、删除、清理日志、恢复数据）需二次确认。

## 三、各功能详细设计

通用约定：
- **输入**：页面表单/查询参数 → REST JSON；**输出**：统一 `{code, msg, data}`（`code=0` 成功）。
- **权限边界**：页面先 `requirePageRole("admin")`（非管理员重定向到各自首页），接口先 `requireRole("admin")` 再按权限点 `requirePerm(code)`，不匹配抛 403。
- **审计**：所有写操作经 `AuditService.run()`，自动计时、自动区分成功/失败、异常继续向外抛（由全局异常处理统一转 JSON）。

### F1 系统监控与状态展示

| 项 | 内容 |
|---|---|
| **操作流程** | 进入 `/admin/monitor`（默认首页）→ 服务端聚合指标一次性渲染 → 可勾选"每 30 秒自动刷新"（前端定时重载） |
| **输入** | 无（或勾选自动刷新开关） |
| **输出** | 业务规模（账号/学生/教师/停用、课程/课时/签到/提交）；运行状态自检 5 项；近 7 日活跃趋势图；各表数据量 TOP10；数据库信息；JVM 与磁盘指标 |
| **权限边界** | `monitor:view`；仅 admin（教师具备该权限点但后台入口仅对 admin 开放） |
| **异常处理** | 每个统计独立 `try/catch`，失败返回空集合并在页面显示 `-`；数据库连接异常时"数据库连接"自检项标红，其余指标照常展示 |

关键设计：把分散指标**翻译成结论**（正常 / 偏高 / 不足 / 待核查），而不是把原始数据丢给管理员自己判断。

### F2 用户与角色管理

| 项 | 内容 |
|---|---|
| **操作流程** | ① 按角色/状态/关键词筛选 → ② 表格分页浏览 → ③ 行内操作（编辑 / 角色 / 重置密码 / 解锁 / 停用 / 删除）→ ④ 弹窗确认 → ⑤ Toast 反馈并刷新 |
| **输入** | 查询：`role`、`status`、`kw`、`page`、`size`；新增：`username`、`real_name`、`role`、`password`、`gender`、`phone`、`class_id`；编辑：除账号与密码外的字段；角色：`role`；状态：`正常/停用`；密码：新密码 |
| **输出** | 分页列表 `{rows,total,page,size,pages}`；单用户详情（含业务引用计数，剔除密码哈希）；用户 CSV |
| **权限边界** | 查询 `user:view`、新增 `user:create`、编辑 `user:update`、删除 `user:delete`、角色 `user:assign_role`、密码 `user:reset_pwd` |
| **服务端强制约束** | ① 不能停用/删除/降级**自己**；② 系统必须保留 ≥1 个启用管理员；③ 有业务数据的账号只能停用不能删除；④ 学生必须指定班级；⑤ 账号 3~32 位字母数字下划线且唯一；⑥ 密码满足系统配置策略；⑦ 密码 BCrypt 哈希，永不回传明文 |
| **异常处理** | 账号重复 → "账号已存在：xxx"；密码过短 → "密码长度不能少于 N 位"；删除被引用 → 提示具体条数并建议改用停用；越权 → 403；参数非法 → 400 级业务提示 |

### F3 权限与访问控制

| 项 | 内容 |
|---|---|
| **操作流程** | 进入 `/admin/perms` → 查看"权限点 × 角色"矩阵（按分组折叠）→ 切换开关 → 即时提交 → 失败自动回滚勾选状态并提示 |
| **输入** | `{role, perm_code, enabled}` |
| **输出** | 矩阵 `{roles:[{code,name,locked}], groups:{组名:[{perm_code,perm_name,admin,teacher,student}]}}`；变更详情（"启用 → 停用"） |
| **权限边界** | 查看 `perm:view`、修改 `perm:update`；admin 列锁定不可改；学生不可获得管理类权限 |
| **异常处理** | 修改 admin → 拒绝并说明"避免系统无人可管"；未知权限点 → 拒绝；学生越权组合 → 拒绝 |

判定顺序：**登录 → 角色粗筛 → 权限点细筛 → 数据归属校验**（如教师只能操作本人课程）。
配置读取失败时回退到内置默认权限（Fail-Safe），保证系统不被配置错误拖垮。

### F4 系统配置与参数管理

| 项 | 内容 |
|---|---|
| **操作流程** | 按分组浏览 17 项参数 → 点"编辑"→ 弹窗按类型输入（string/int/decimal/bool 分别用文本框、数字框、下拉）→ 保存 → 提示"改前 → 改后" → 可"恢复默认" |
| **输入** | `{config_key, config_value}`；恢复默认：`/api/admin/config/{key}/reset` |
| **输出** | 分组配置列表；修改结果（变更详情字符串） |
| **权限边界** | 查看 `config:view`、修改 `config:update`；`editable=0` 的只读项（如会话超时）界面禁用并标注"需重启后生效" |
| **校验规则** | 类型校验（int/decimal/bool/string）；范围校验（密码长度 4~32、锁定阈值 0~20、预警分 0~100、出勤率与置信度 0~1、日志保留 7~1095）；业务规则（黄色线必须高于红色线） |
| **异常处理** | 类型不符/越界/违反业务规则 → 返回具体原因，不落库；配置键不存在 → 拒绝；只读项 → 提示改配置重启 |

生效方式：修改后**立即刷新内存缓存**并影响业务（顶栏名称、风险分级、密码策略、AI 复核阈值、备份目录等）；只读项明确标注需重启。

### F5 操作日志与审计追踪

| 项 | 内容 |
|---|---|
| **操作流程** | 概览卡（总数/今日/失败）→ 按模块/结果/关键词/时间范围筛选（含"近 7 天"快捷）→ 分页流水 → 点"详情"看完整信息 → 可导出 CSV、可按保留天数清理 |
| **输入** | `module`、`result`、`kw`、`operatorId`、`from`、`to`、`page`、`size`；清理：`days` |
| **输出** | 分页流水；详情（操作人/时间/模块/操作/对象/结果/失败原因/变更详情/IP/客户端/耗时）；CSV；清理条数 |
| **权限边界** | 查看 `log:view`、导出 `log:export`、清理 `log:purge` |
| **记录范围** | 管理后台全部写操作 + 登录/登出；成功与失败同记；`detail` 记录"改前 → 改后"，`operator` 冗余存账号（用户被删仍可追溯） |
| **异常处理** | 截止日期自动补 `23:59:59`（避免当天查不到）；清理天数越界拒绝；写日志失败只告警不影响主业务；导出上限 5000 条 |

### F6 数据备份与恢复

| 项 | 内容 |
|---|---|
| **操作流程** | 备份：点"立即备份" → 生成 `库名_时间戳.sql` → 记录大小/表数/行数/耗时 → 列表可下载/删除。恢复：点"恢复" → 弹窗展示风险 → **输入文件名确认** → 系统先自动备份当前库 → 执行恢复 → 返回耗时 |
| **输入** | 备份：无；恢复：`{confirm: 文件名}`；删除/下载：`backup_id` |
| **输出** | 备份记录列表（文件名/类型/大小/表数行数/状态/耗时/操作人/时间/文件是否存在）；恢复结果（引擎、语句数、失败数、恢复前备份文件名、耗时）；文件下载流 |
| **权限边界** | 查看 `backup:view`、创建 `backup:create`、恢复 `backup:restore`、删除 `backup:delete` |
| **双引擎** | 优先 `mysqldump` / `mysql` 命令行；不可用或失败时自动降级为**内置 JDBC 逻辑转储**（`SHOW CREATE TABLE` + 每 200 行一条批量 INSERT，视图最后重建） |
| **异常处理** | 备份失败仍落记录（status=失败 + 原因）并提示；恢复前自动备份失败不阻断但告警；文件缺失 → "备份文件已不存在"；确认信息不匹配 → 拒绝；状态为失败的备份不可用于恢复；部分语句失败 → 返回失败条数并提示检查 |

## 四、功能之间的关联关系

```
                        ┌──────────────┐
                        │  系统配置 F4  │
                        └──────┬───────┘
        密码策略 ──────────────┼───────────── 备份目录 / 引擎路径
        预警阈值 ───────┐      │      ┌───────────── 日志保留天数
        系统名称 ───┐   │      │      │
                   ▼   ▼      ▼      ▼
┌────────────┐   ┌──────────────┐  ┌────────────┐   ┌──────────────┐
│ 认证/登录   │◀──│ 用户与角色 F2 │  │ 权限配置 F3 │   │ 数据备份 F6   │
└─────┬──────┘   └──────┬───────┘  └─────┬──────┘   └──────┬───────┘
      │                 │                │                 │
      │ 登录失败/锁定     │ 角色决定权限     │ 权限点决定教师端   │ 恢复前自动备份
      ▼                 ▼                ▼                 ▼
┌────────────────────────────────────────────────────────────────┐
│                     操作日志与审计 F5（全部动作留痕）               │
└───────────────────────────────┬────────────────────────────────┘
                                ▼
                    ┌───────────────────────┐
                    │  系统监控 F1（规模/健康）│
                    └───────────────────────┘
```

关键关联说明：

1. **F2 → F3**：用户的 `role` 决定其权限集合；改角色即改权限，改权限矩阵即时影响该角色所有成员。
2. **F3 → 业务接口**：教师端课堂/互动/作业/AI 批改写操作校验权限点，管理员停用某权限后教师端立即不可用。
3. **F4 → F2 / F6 / F5 / 业务**：密码策略校验新建与重置密码；预警阈值进入学情风险分级；备份目录与命令行路径决定 F6 行为；日志保留天数是 F5 清理的默认依据；系统名称实时改顶栏。
4. **F2 → 认证**：停用账号禁止登录；重置密码顺带解锁；连续失败锁定由配置驱动，管理员可手动解锁。
5. **F2/F3/F4/F5/F6 → F5**：所有写操作自动产生审计记录，F5 是其他功能的"证据链"。
6. **F6 → F5/F1**：备份恢复本身产生两条记录（恢复前自动备份 + 恢复动作）；监控页展示失败操作数与备份磁盘余量。

## 五、数据模型（系统管理层）

| 表 | 作用 | 关键设计 |
|---|---|---|
| `sys_config` | 系统参数 | `config_key` 唯一；值统一字符串 + `config_type` 解析；`editable=0` 表示只读；记录 `updated_by/updated_at` |
| `sys_permission` | 权限点 | `perm_code` 唯一，`builtin=1` 不可删 |
| `role_permission` | 角色 × 权限 | `UNIQUE(role, perm_code)` + `CHECK(role)`，勾选即写本表 |
| `operation_logs` | 审计流水 | `operator` 账号冗余；记录 `result/fail_reason/ip/user_agent/cost_ms`；`created_at/operator_id/module` 建索引 |
| `backup_records` | 备份记录 | 文件名/路径/大小/类型/库名/表数/行数/状态/耗时/操作人 |

统计类查询（表数据量、活跃趋势、业务总览）由 `SysMapper` 直接 SQL 聚合，监控页不做内存计算。

## 六、非功能设计

- **安全**：BCrypt 哈希存储密码、绝不回传哈希；登录失败计数与锁定；管理接口双重校验（角色 + 权限点）；危险操作二次确认；恢复需输入文件名确认；CSV 导出不含敏感字段。
- **性能**：配置与权限走内存缓存（`ConcurrentHashMap`），变更即刷新；用户/日志分页查询（默认 10/20 条）；备份单条 INSERT 批量 200 行；监控指标单次聚合。
- **可用性**：监控、日志、备份任一环节失败均降级而非报错页；写日志失败只告警；备份引擎自动降级；配置缺失回退内置默认值。
- **可维护性**：权限点与配置项集中在 `SysConfigService` 的常量定义中，新增只需加一行；控制器统一通过 `audit.run()` 包装，审计逻辑零重复。

## 七、验证

```powershell
# 应用已启动（默认 8080，其他端口加 -Base）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\admin_smoke.ps1 -Base http://127.0.0.1:8081
```

覆盖 33 项：管理员登录与首页路由、6 个页面可访问、5 个查询接口、用户增删改查（含重复账号/弱密码/停用/改密/删除）、配置修改与范围校验与恢复默认、审计留痕、权限边界（admin 锁定、学生不可提权）、备份创建与列表、非管理员访问被拒（接口 403 / 页面 302）。

实测结果：`pass=33 fail=0`；备份 3.7 MB / 20 表 / 38,939 行耗时 0.4~0.8 s；恢复含自动备份共 2.4 s，恢复后数据一致。
